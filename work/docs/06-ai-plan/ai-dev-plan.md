## 3. Token 消耗与产出比预估(三档,包月配额口径不折价)

### 3.1 校准推导(两路复算闭合)

1. **基线(台账实测)**:阶段 5 ui 子代理 6,835,123 token 产出 `UI/` 33 文件 ≈ 22,400 行(32 屏 × ~700 行估算,置信度低-中)→ **≈305 token/行(输入+输出合计/有效行)**。其余台账:tech-stack 447,673 / scout 1,256,450 / market 902,690 / feature-list 163,221 / ux 446,449;0–5 阶段合计 ≈10.05M(文档类,佐证量级)。
2. **编码调整系数 ×1.2 → 中性 366 token/有效行**:代码单行输出 token 密度低于长 HTML(约 −50%),但测试-修复迭代轮次多于静态原型一次生成(返工 ×1.5–2),上下文装载更重(引擎/SDK 文档);综合净 ×1.2(经验判断,置信度低-中,A-615)。三档:**乐 300 / 中 366 / 保 480** token/行(保档含预研推翻返工与真机联调多轮)。
3. **有效代码行两路估**:
   - 路 A(模块法):客户端 Unity ≈28K(A 3.5K/B 4K/C 5.5K/D 3.5K/E 2.5K/F 3K/G 1.5K/H+I/J/K 2.5K+测试)+ 服务端 ≈18K(L 2.5K/M 1.5K/N 2K/O 4K/P 2K/Q 1.5K/R 2.5K/S+T 1K+测试)+ 后台 ≈6K + POC/验收脚本 ≈2K = **54K 行**;

   - 两路差 2.3% → 取 **53,000 行**。
4. **总量复算闭合**:53,000 × 366 = **19.40M**(中);乐 53,000×300 = 15.90M;保 53,000×480 = 25.44M。与批次加权分配(下表)合计一致 ✓。开发期中档 ≈ 前期文档阶段总耗(10.05M)的 1.9 倍,与体量/时长比例相称。
